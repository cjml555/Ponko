Solución de problemas

El modelo no carga

  • Abre el log de carga en Modelos/API: la traza indica si falta memoria, el formato no es válido o el archivo está incompleto.
  • Comprueba el espacio libre y que el archivo se copió entero (tamaño esperado).
  • Prueba una cuantización menor (Q4) o un modelo más pequeño.

Va muy lento

  • Baja el tamaño de contexto o la salida máxima.
  • Usa un modelo más pequeño o Q4 en lugar de Q8.
  • Ajusta hilos de CPU en Ajustes (por defecto usa todos los núcleos).
  • Mide con el benchmark antes y después de cada cambio.

El modelo LiteRT responde en chino

Es un defecto del modelo o de su plantilla, no de la app. Usa la variante GGUF del mismo modelo, que respeta el idioma y el system prompt.

GPU no disponible / cae a CPU

Si el teléfono no expone un dispositivo Vulkan o el driver falla, la app continúa en CPU y lo avisa. El dibujo con GPU todavía no está validado en hardware real.

Las imágenes no se generan

  • Confirma que el modelo de dibujo está cargado (no solo seleccionado).
  • Revisa que el tamaño sea múltiplo de 64 y que los pasos/CFG sean coherentes con el sampler.
  • Con LCM-LoRA: pasos 4–8 y CFG 1.5–2.

El tagger devuelve etiquetas raras

Cambia Orden de canales (BGR ↔ RGB). Si salen muy pocas, baja el umbral.

La API no responde desde otra máquina

  • Comprueba que el servicio está Running y en qué puerto.
  • Ambos dispositivos deben estar en la misma red; revisa el firewall del router (aislamiento de clientes).
  • Si defines clave, envíala como Authorization: Bearer ….
  • La API se apaga al reinstalar o reiniciar: vuelve a iniciarla.

HTTP bloqueado

Las builds de release solo permiten HTTPS. Para un endpoint local usa la build de debug, que habilita tráfico en claro.

Un mensaje no cabe en el contexto

El límite por defecto es 4096 tokens. Inicia un chat nuevo, envía un archivo más corto o menos turnos.

La app se cierra al cargar

Probablemente falta memoria (OOM). Cierra otras apps, usa un modelo menor o una cuantización más agresiva. El registro de fallos queda guardado y se muestra en el siguiente arranque.
